# Content guide

Wonderly does not ship a hand-written question bank. Questions are produced on
the device, and every one passes code before a child can see it.

## Where questions come from

| Set | Source | Detail |
|---|---|---|
| Mammals, Zoology Quiz, Birds, Ocean life, Plant ecosystems, Word wizard | On-device language model | `QuestionGenerator` + `BankFiller`; stored in `GeneratedBank` |
| Number fun | Dart (`ProceduralGenerator.numbers`) | Add, subtract, multiply, divide; difficulty follows the learner's grade |
| Geometry shapes | Dart (`ProceduralGenerator.geometry`) | Two drag-and-match rounds, shape picks, side and corner counts |
| Logic puzzles | Dart (`ProceduralGenerator.patterns`) | Repeating shape patterns (AB, AAB, ABB, ABC) |
| Safety net | `assets/data/questions.json` | Only used until the model has written a full round |

The model is used for open-ended facts and wording. Anything with an exactly
computable answer is generated by code, so it cannot be wrong.

## The generation pipeline

```
SetBlueprint (topic) + learner grade
   -> prompt (system rules, topic, "do not repeat" list)
   -> on-device model, JSON-schema constrained where the engine supports it
   -> parse: one JSON object, 4 distinct string options, answer 0..3
   -> ContentSafety: allowed characters, blocklist, length
   -> ValidateQuestion: prompt <= 15 words, valid answer index
   -> duplicate check against the bank
   -> second pass: the model answers WITHOUT the key and must pick the same option
   -> options shuffled, stored with a content-hash id
```

Rejected candidates are discarded and retried (3 attempts per question, and the
run stops after 6 consecutive failures). The bank holds `3 x quizSize` questions
per set; each completed round shows the next window of the bank.

## Changing the curriculum

Everything is in `lib/features/learning/domain/entities/set_blueprint.dart`
(`Curriculum.blueprints`):

```dart
SetBlueprint(
  id: 'space',                       // unique, snake_case
  subject: Subject.zoology,          // pick the closest subject (or add one)
  title: 'Space',
  art: 'sun',                        // illustration key (see art_view.dart)
  source: QuestionSource.llm,        // or procedural
  topic: 'planets, the sun, the moon, stars and astronauts',
  unlockStars: 30,                   // optional
)
```

Procedural sets also need a branch in `CatalogAssembler._procedure`. Add tests
next to `test/unit/ai/ai_domain_test.dart`.

## Tuning quality and safety

- Blocklist and character rules: `ContentSafety`.
- Prompt wording and schema: `QuestionGenerator._systemPrompt`, `schema`.
- Structural rules shared with the safety net: `ValidateQuestion`.
- If too many candidates are rejected on a target phone, offer the larger model
  profile instead of loosening checks.

## Safety-net file

`assets/data/questions.json` is parsed by `CatalogParser` and validated by the same
rules; a test fails if an authored question is rejected. Keep it small and
fact-checked by a second person. It exists so the app is fully usable on a phone
that cannot run the model and on first launch.
